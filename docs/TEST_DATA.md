```powershell
cd C:\Users\KRISHNA\OneDrive\Desktop\eventrahq
```

The command is restricted to `APP_ENV=local` and the approved development project `kqcevtlhhyxkjnxsjjcz`. It asks for:

2. A Supabase **secret key**, or legacy **service_role key**, from this project's Settings → API Keys. The existing publishable key cannot create accounts. Input is hidden. This privileged key is used only by this command and is not saved.
3. The project's **postgres administrator** direct or session-pooler connection URL, on port 5432, ending in `?sslmode=verify-full`. Use the connection information from the dashboard's Connect panel. Do not paste either credential into chat, source files or browser code. No Auth configuration is changed, no invitation/confirmation emails are sent, and no resources are provisioned. Only the explicitly labeled test accounts are created as email-confirmed via the Auth Admin API. Ordinary customer email verification remains enabled. ## Find the login credentials

After a successful run, open this local ignored file:

```powershell

```

It contains a separately generated random password for each test account, its Auth ID, `login_verified` status and the dataset's `database_seeded` status. Passwords are generated once and retained for safe resumption. They are never committed or printed to the terminal. Do not share or remove this file while the test dataset is in use.

## Repeat runs and failures

Business data is inserted in one transaction through the existing workflow commands, with a completion marker and transaction lock. Repeat runs leave the existing dataset and subsequent user edits untouched. Existing unrelated account/email collisions stop the command; passwords are never reset. There is no reset/delete mode.

Auth account creation cannot share a database transaction. A partial failure may leave some real test accounts created before the business-data transaction starts. Their passwords are retained in the ignored state file; rerunning the same command resumes safely. Keep that file. If it is lost, stop and review the test accounts rather than resetting unknown users or recreating passwords.

The command does not turn off RLS, weaken runtime privileges, disable confirmation globally, create simulator payments, or write to production. This development dataset must not be promoted into production.
